A primeira tentativa de EditMode no novo worktree não gerou XML: o Unity caiu na importação inicial com asserção de thread. Após o cache de importação ficar pronto, a repetição produziu XML `Passed` 9/9. Essa falha inicial não foi contada como `pass`. A execução PlayMode seguinte produziu XML `Passed` 7/7. O build confirmou sucesso no log do Editor; os arquivos gerados ficam ignorados pelo Git.

Os testes controlados cobrem recurso homônimo em ambientes distintos, API→banco compartilhado, ciclo, revogação de vínculo, perda de fonte/coleta, timeout, 401, 503, expiração, reinício, leitura tardia, recuperação evidenciada, coleta periódica sem sessões e persistência de incidente. A falha de coleta mostra `sem_dados` com cobertura perdida; não resolve o incidente anterior. A sonda de host lê memória local pontualmente no teste com saúde `sem_dados`, evitando classificar uso de RAM como saúde do host. Os testes HTTP usam respostas falsas; nenhuma API do laboratório de jogo foi sondada. A API de produção autorizada foi observada em ensaio pontual separado.

A cena demonstrativa contém racks lógicos e painel de recurso com ambiente, saúde, frescor, cobertura, fonte, horário, indicador, evidência e projetos dependentes. Seus valores vêm de fixture sintética e mantêm o selo `CONCEITO · DADOS ILUSTRATIVOS`. A cena live separada consome snapshot/SSE de serviço local e não inclui carregadores da demonstração; seu ensaio inicial de transporte usou fonte sintética, seguido da [prova pontual com Player e fontes HTTP locais reais](player-operacional.md). A nova configuração liga sondas host/HTTP explicitamente autorizadas ao processo do serviço; o teste standalone coletou memória real do host local, mas não instalou coleta contínua de laboratório. O proxy Docker foi ensaiado pontualmente; banco não possui conector ativo. A #3 foi reaberta, e a #16 continua rastreando os critérios operacionais restantes.

O novo teste PlayMode detectou que o carregador M2 não era reconstruído ao reabrir a cena. Renomear o arquivo C# para corresponder ao `MonoBehaviour` serializado corrigiu o vínculo; a cena foi recriada e EditMode, PlayMode e build foram repetidos no código corrigido.

Revisão automática da PR #9: o corpo HTTP aberto após receber cabeçalhos e o status de recurso preservado ao filtrar uma sala sem vínculos foram reproduzidos e corrigidos. Regressões de cancelamento do corpo e troca de filtro passaram; serviço, PlayMode e build foram repetidos após as correções.

Revisão automática da PR #11: o snapshot podia misturar sessões antigas e sequência SSE nova quando outro processo escrevia no SQLite. A composição passou a ocorrer em uma transação de leitura; teste com duas conexões confirmou visão consistente. O código corrigido foi mesclado antes das PRs seguintes. EditMode, PlayMode e build Windows foram repetidos na nova fatia baseada em `b9c640f`; a execução posterior do Player com fontes locais está registrada separadamente.

Levantamento de permissões e fontes: [laboratório](laboratorio.md).
